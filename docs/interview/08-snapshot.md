# 08　文件快照：撤回修改，也能撤回一次回退

用户要求修复 parser.py 后，可能想保留对话但恢复代码，也可能一起退回对话。快照服务保存工具实际修改前后的文件版本，回退时检查用户后来有没有改过这些文件。

## 工具前后各保存一次

应用将 SnapshotService.before_tool_call 与 after_tool_call 接到有序工具钩子。获准的 write、command 工具执行前采集 before，执行后采集 after；差异路径与两棵树保存在工具结果的 file_snapshot 中。被 gate 拦截的工具不会运行，也不触发执行后钩子。

GitSnapshotStore 使用独立 repository.git 和 snapshot.index，不借用户暂存区保存快照。采集排除应用数据、内部目录和忽略内容，限制未跟踪大文件；非 Git 项目返回不可用。I/O 在锁内交给线程，取消仍等待已开始的操作结束。

## 直接回退，先检查冲突

CLI 的 `pycode revert <target> --mode dialogue|code|both` 调用具体 SnapshotService.revert。调用方使用会话 execution 上下文，防止与运行或分支切换并发。普通目标保留目标自身，选择目标之后的记录；root 表示全部历史。对同一路径，最早 before 是目标版本，最后 after 是预期当前版本。

## 回退本身也留下可撤销记录

服务追加 kind=revert 的 custom 记录，保存 previous_leaf、resulting_leaf、范围及实际 file_snapshot。再次以最新 revert 记录为目标时，读取这条记录自己的快照，恢复回退之前的文件与原 dialogue leaf。只能撤销当前分支最新的 revert，避免从别处猜测原始分支。

多文件恢复不是事务。写到一半失败时，服务尝试重新采集实际状态并记录已经变化的路径，报告 revert_partial；如果最终快照或记录也失败，错误明确表示文件可能已变且无法保证有可撤销记录，不能宣称已经自动补偿。

## 框架和服务各负责什么

Deep Agents 调用工具；ToolExecutor 依次执行权限检查和显式钩子；SnapshotService 处理快照与回退；GitSnapshotStore 保存字节。快照不会批准工具，也不会调用模型。memory 的文件根被排除，避免把长期笔记作为代码一起回退。

阅读时重点核对三个边界：普通 target 不包含自身；撤销 revert 读取其自身快照；部分失败后的记录只是已知事实，不是多文件原子恢复保证。
